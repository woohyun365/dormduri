# 시즌 참여자 등록 정책

## 문서 범위

이 문서는 `시즌 참여자 등록`의 의미, `SeasonParticipantProfile` draft/final 상태, 기숙사 선택 기반 registration finalize, public summary/detail/action capability 같은 cross-cutting 규칙을 다룬다.

- 시즌 상태와 기능 on/off: [season-lifecycle.md](./season-lifecycle.md)
- 가입/매칭 자격: [access-eligibility.md](./access-eligibility.md)
- 프로필 구조와 수정 가능 범위: [profile-model.md](./profile-model.md)
- 매칭 요청/확정 가능 조건: [matching-lifecycle.md](./matching-lifecycle.md)
- 채팅 가능 조건: [chat-lifecycle.md](./chat-lifecycle.md)
- 룸메이트 찾기 검색 scope/필터/정렬: [roommate-searching.md](./roommate-searching.md)

이 문서가 **시즌 참여자 등록의 의미와 registration 완료 조건의 최종 소유 문서**다.

## 핵심 정의

| 개념                      | 정책                                                                                                                                                                                                                                                                                                                                                                                                                      |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 시즌 참여자 row           | current season에서 사용자를 추적하는 `SeasonParticipant` row. row 존재 자체는 등록 완료가 아님                                                                                                                                                                                                                                                                                                                            |
| season profile draft      | registration 전 `SeasonParticipantProfile` current draft. self read/write에는 보이지만 public target/history row가 아님                                                                                                                                                                                                                                                                                                   |
| dormitory selection draft | registration 전 사용자가 선택한 current season 기숙사. `dormitorySelectionState = SELECTED`, `dormitoryId != null`로 저장되며 registration 완료 전까지 변경 가능. complete season profile은 이 draft 저장 조건이 아니라 registration completed 조건이다                                                                                                                                                                   |
| registration candidate    | complete season profile, account academic identity, season additional profile, valid dormitory selection draft를 가지고 시즌 등록 finalize가 가능한 상태                                                                                                                                                                                                                                                                  |
| registration 완료         | `participationIntent = REGISTERED`, `registeredAt != null`, `dormitorySelectionState = ASSIGNED`, `dormitoryId != null`, complete lifestyle/condition, account `UserAcademicIdentity(collegeCode, birthYear)`, season additional `grade` + full `mbti`, `SeasonParticipantProfileHistory(source = SEASON_REGISTRATION, registeredAtSnapshot)`가 같은 finalize 흐름에서 확정된 상태. `intro`는 optional이며 빈 문자열 가능 |
| public summary            | roommate-search card용 최소 projection. detail/action/score 권한과 분리                                                                                                                                                                                                                                                                                                                                                   |
| detail view               | `detailViewable/canViewFull = true`일 때만 열리는 profile detail API                                                                                                                                                                                                                                                                                                                                                      |

중요:

```text
SeasonParticipant row 존재
≠ season profile draft 존재
≠ registration 완료
≠ public target 노출 가능
≠ detail/score/action 가능
≠ match/chat 가능
```

즉, registration은 **complete lifestyle/condition + account academic identity + season additional profile + 저장된 valid dormitory selection draft + participant finalize**이고, public exposure/match/chat은 그 이후 capability owner가 추가 조건을 본다. `intro`는 registration blocker가 아니며 미작성 시 빈 문자열 snapshot으로 고정한다.

## Registration complete 입력 계층

Registration complete 판정은 하나의 season profile row만 보지 않고 아래 입력 계층을 함께 본다.

| 계층                               | owner                      | registration complete 요구                                                                                                                                                                                                                                                                                                 |
| ---------------------------------- | -------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Account display identity           | `UserDisplayIdentity`      | nickname snapshot source. Current season registration 완료 뒤 일반 사용자 변경은 registration snapshot lock으로 잠김                                                                                                                                                                                                       |
| Account academic identity          | `UserAcademicIdentity`     | `collegeCode`, `birthYear` 필수. Active verified account invariant이며 registration readiness input이다. Registration finalize 시 season profile/history snapshot으로 복사. Current season registration 완료 뒤 일반 사용자 변경은 registration snapshot lock으로 잠기며 `ACADEMIC_IDENTITY_LOCKED_BY_REGISTRATION`을 반환 |
| Season profile lifestyle/condition | `SeasonParticipantProfile` | 수면 6 + 생활 8 + 원하는 룸메 조건 8개 필수                                                                                                                                                                                                                                                                                |
| Season additional profile          | `SeasonParticipantProfile` | `grade`, full `mbti` 필수                                                                                                                                                                                                                                                                                                  |
| Optional intro                     | `SeasonParticipantProfile` | 입력 optional, 미작성 시 빈 문자열 `''`로 저장/응답. Registration blocker가 아님                                                                                                                                                                                                                                           |
| Dormitory selection draft          | `SeasonParticipant`        | registration 전 저장된 valid `SELECTED + dormitoryId`가 finalize에서 `ASSIGNED`로 확정되어야 함                                                                                                                                                                                                                            |

`UserAcademicIdentity`가 없는 active verified user는 account identity invariant가 깨진 상태이므로 current-user도 `ACCOUNT_IDENTITY_INCOMPLETE / USER_ACADEMIC_IDENTITY_REQUIRED`로 fail-closed한다. Registration finalize는 해당 상태를 정상 draft/readiness incomplete 상태로 취급하지 않고 fail-closed한다. Signup/auth가 lifestyle/intro를 만들지 않는다는 invariant는 유지하되, account setup 단계에서 academic identity는 별도 owner로 수집한다. Registration snapshot lock은 nickname과 academic identity에 공통으로 적용되는 잠금 축이며, current season의 final snapshot과 live account identity가 서로 달라지는 것을 막는다.

## 시즌 참여자 등록 가능 시점

| 시즌 상태           | season profile create/edit | dormitory selection draft write/change                                                                                                              | registration finalize | 비고                                                                                          |
| ------------------- | -------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------- | --------------------------------------------------------------------------------------------- |
| `OFF_SEASON`        | 불가                       | 불가                                                                                                                                                | 불가                  | 시즌 도메인 밖. profile tab은 nickname/self history read 중심                                 |
| `SEASON_OPEN`       | registration 전 가능       | registration 전 저장/변경 가능. participant row가 없으면 row/container ensure 후 `dormitorySelectionState = SELECTED`, `dormitoryId != null`만 갱신 | 가능                  | selection 저장은 profile 완성 전에도 가능. finalize는 complete profile + valid selection 필요 |
| `SEASON_MATCHING`   | registration 전 가능       | registration 전 + 선택 dormitory의 `roomSelectionDate` 전까지 저장/변경 가능                                                                        | 가능                  | finalize 시 저장된 selection draft가 여전히 valid해야 함                                      |
| `SEASON_POST_MATCH` | 불가                       | 불가. 기존 selection은 read-only                                                                                                                    | 불가                  | 결과 확인/정리 기간                                                                           |

Dormitory selection draft는 별도 `UserDormitorySelection`/account-level row가 아니라 current season `SeasonParticipant` row의 `dormitorySelectionState`와 `dormitoryId` columns로 표현한다. selection 저장은 participant row/container ensure를 허용하지만, `REGISTERED`, `registeredAt`, `ASSIGNED`, `SeasonParticipantProfileHistory`를 생성하지 않는다. registration 이후에는 profile뿐 아니라 dormitory selection write도 잠긴다.

Signup/auth는 season profile을 생성하지 않는다. 사용자는 시즌 기간에 별도 season profile create/edit 흐름으로 profile draft를 만든 뒤 registration을 진행한다.

## SeasonParticipantProfile lifecycle

| 시점                                            | canonical owner                                                                      | 정책                                                                                                                                                                                                                                    |
| ----------------------------------------------- | ------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| signup/auth                                     | `User`, `UserDisplayIdentity`                                                        | 계정과 nickname identity만 생성. profile orchestration 없음. Auth API는 lifestyle/condition/intro/profile object를 받지 않음                                                                                                            |
| `SEASON_OPEN`/`SEASON_MATCHING` registration 전 | `SeasonParticipantProfile` current draft                                             | create/edit 가능. history row를 만들지 않고 `updatedAt`만 갱신                                                                                                                                                                          |
| registration finalize                           | `SeasonParticipant` + `SeasonParticipantProfile` + `SeasonParticipantProfileHistory` | complete lifestyle/condition, account academic identity, season additional profile, 저장된 valid dormitory selection draft를 같은 transaction에서 확정하고, current row를 final/read-only로 잠근 뒤 `SEASON_REGISTRATION` snapshot 생성 |
| registration 이후                               | `SeasonParticipantProfile` final/read-only                                           | 해당 season의 current aggregate로 유지. profile 전체 잠금. optional additional fields도 함께 잠금                                                                                                                                       |
| 과거 season read                                | `SeasonParticipantProfileHistory`                                                    | registration/retention snapshot 기준 read-only. current row 삭제나 다음 시즌 이월의 대체물이 아님                                                                                                                                       |

- `SeasonParticipantProfile` current row는 current season draft/final aggregate다. `seasonEndDate`는 이 row의 삭제 이벤트가 아니며, 다음 시즌은 새 `SeasonParticipant` + 새 `SeasonParticipantProfile` draft로 시작한다.
- registration 완료 시 `SeasonParticipantProfile.nicknameSnapshot`에는 당시 live `UserDisplayIdentity.nickname`을 고정한다. Search summary/detail/history는 snapshot nickname을 우선 사용하고, current-user 계정/설정 화면은 live `UserDisplayIdentity`를 사용한다. 다만 current season에서 현재 registration 완료 상태인 동안 일반 사용자 live nickname 변경은 잠겨 snapshot과 live identity 불일치를 만들지 않는다.

`UserProfile` / `UserProfileHistory`는 canonical profile 계층에서 제거한다.

## 기숙사 선택 / registration finalize 경계

기숙사 선택은 current season registration step이며, `PATCH /api/users/me` profile patch가 소유하지 않는다. 별도 season participation / dormitory selection API/service가 아래 책임을 가진다.

| 책임            | 정책                                                                                                                                                                                                                                                                |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 선택 목록       | current season operated dormitory만 노출                                                                                                                                                                                                                            |
| campus 검증     | dormitory campus는 participant `campusCodeSnapshot`과 일치해야 함                                                                                                                                                                                                   |
| gender 검증     | dormitory `genderPolicy`는 participant `genderSnapshot`과 호환되어야 함                                                                                                                                                                                             |
| cutoff 검증     | `SEASON_MATCHING`에서는 해당 dormitory의 `roomSelectionDate` 이후 finalize/match action 불가                                                                                                                                                                        |
| selection write | valid selection이면 registration 전 `dormitorySelectionState = SELECTED`, `dormitoryId != null`로 저장한다. 이 단계는 `REGISTERED`, `registeredAt`, profile history를 만들지 않으며, complete profile을 요구하지 않고 registration 전까지 변경 가능                 |
| finalize        | 저장된 selection draft, complete lifestyle/condition, account academic identity, season additional profile을 다시 검증한 뒤 `dormitorySelectionState = ASSIGNED`, `registeredAt`, profile history snapshot을 확정. registration completed는 이 조건을 모두 요구한다 |
| unavailable     | operated dormitory가 없거나 검증 가능한 선택지가 없으면 `UNASSIGNED` 완료가 아니라 registration unavailable / selection unavailable로 반환                                                                                                                          |

`REGISTERED + UNASSIGNED`는 더 이상 참여 완료 상태가 아니다. 기숙사 선택 전 상태는 selection-required 상태로, 선택 저장 후 등록 전 상태는 `SELECTED` registration candidate로 표현한다.

## 시즌 참여 철회 / 재등록 / 계정 삭제와의 분리

시즌 참여 등록 이후의 off-ramp는 **계정 삭제 pending 처리**가 아니라 **시즌 참여 철회(de-registration)** 로 처리한다.

| 항목              | 정책                                                                                                            |
| ----------------- | --------------------------------------------------------------------------------------------------------------- |
| 허용 상태         | `SEASON_OPEN`, `SEASON_MATCHING`                                                                                |
| 불가 상태         | `SEASON_POST_MATCH`                                                                                             |
| 확정 상대 보유 시 | live `ActiveMatch`가 있으면 철회 불가                                                                           |
| 철회 후 재참여    | 같은 season에서 `WITHDRAWN` / `DECLINED` / `withdrawnAt` 이력이 있으면 기본 거부. 예외 정책은 별도 이슈         |
| 처리 의미         | 시즌 참여자 current state를 `WITHDRAWN` 계열로 종료하고, 미결 request/비매칭 thread를 withdrawn reason으로 정리 |

계정 삭제 요청은 retention/de-identification 이벤트이고, 시즌 참여 철회와 같은 상태 전이가 아니다. 현재 시즌에 등록 중인 사용자의 계정 삭제 요청은 수락하지 않으며, 먼저 시즌 참여 철회가 가능한지 안내받거나 시즌 종료 후 다시 삭제를 요청해야 한다.

## SeasonParticipant lifecycle event log / audit trace

`SeasonParticipant`의 `joinedAt`, `activatedAt`, `matchedAt`, `withdrawnAt`, `expiredAt`, `hiddenByAdminAt`, `deactivatedAt` 같은 current-state timestamp columns는 사용자-facing 상태 조회의 source of truth로 유지한다.

`SeasonParticipantLifecycleEvent`는 event sourcing/read-model rebuild를 위한 canonical 상태 저장소가 아니라 운영/audit/debugging용 append-only trace다. 현재 제품 구현은 실제 mutation owner가 있는 전이에 한해 아래 event를 같은 transaction boundary에서 남긴다.

| event       | owner                               | 의미                                                                                                   |
| ----------- | ----------------------------------- | ------------------------------------------------------------------------------------------------------ |
| `JOINED`    | current season participant backfill | 운영 캠퍼스/current season에 대해 eligible user의 participant container row가 생성됨                   |
| `ACTIVATED` | registration finalize               | complete profile + valid dormitory selection + account identity가 확정되어 registration 완료 상태가 됨 |
| `WITHDRAWN` | de-registration command             | 사용자가 시즌 참여 철회를 완료하고 pending match/chat side effect가 정리됨                             |

Lifecycle event metadata는 allowlist key만 저장한다. Raw lifestyle/profile body, internal audit payload, stack trace, email, token 같은 민감값/PII는 저장하지 않는다.

이 hot event log는 participant lifecycle에 종속되는 운영 trace다. 계정 삭제/비식별화 이후에도 법적·분쟁·신고 대응을 위해 보존해야 하는 원문/식별 payload는 이 log가 아니라 [data-retention.md](./data-retention.md)의 RRPD/retained vault와 retention access log 경계를 따른다.

## Participant visibility / safety projection 소비 원칙

`SeasonParticipant.hiddenByAdminAt`, `hiddenReasonCode`, `hiddenReasonDetail`, `deactivatedAt`는 season-participants가 빠르게 읽는 **current visibility projection**이다. 신고 접수 원장, user-specific block relation, BackOffice review queue는 이 column의 source of truth가 아니며, 후속 social-safety/moderation owner가 review/system/admin decision 이후 projection을 갱신하는 구조로 본다.

| 상태 / projection                                       | profile draft / dormitory selection / 시즌 참여 확정 | public target summary/detail               | 신규 bookmark/match/chat action | source owner                                                  |
| ------------------------------------------------------- | ---------------------------------------------------- | ------------------------------------------ | ------------------------------- | ------------------------------------------------------------- |
| `hiddenByAdminAt` + `hiddenReasonCode`                  | 거부                                                 | 닫힘 (`visible=false`)                     | false                           | future social-safety/moderation decision → current projection |
| `deactivatedAt`                                         | 거부                                                 | 닫힘 (`visible=false`)                     | false                           | season lifecycle/admin/system decision                        |
| `WITHDRAWN` / `withdrawnAt` / `DECLINED` / `declinedAt` | 거부                                                 | 닫힘 (`registered=false`, `visible=false`) | false                           | de-registration / registration decision                       |
| `EXPIRED` / `expiredAt`                                 | 거부                                                 | 닫힘 (`registered=false`, `visible=false`) | false                           | season lifecycle                                              |
| account `deletedAt` 또는 deidentified target            | 거부 또는 target deleted/deidentified tombstone      | 닫힘                                       | false                           | users/retention                                               |

`ParticipantHiddenReasonCode`는 `POLICY_VIOLATION`, `SAFETY_REVIEW`, `ADMIN_REQUEST`, `OTHER` 의미로 유지한다. `REPORT_REVIEW`처럼 신고 접수만으로 hidden 확정처럼 보이는 값이나, `USER_PROTECTION`처럼 viewer-specific block과 participant-level hidden을 섞는 값은 현재 taxonomy에 넣지 않는다.

## public summary/detail/action capability 원칙

Public/shared contract에서는 `LIMITED/FULL` exposure enum을 사용하지 않는다. 아래 capability를 분리해서 계산한다.

### capability 계층

| 축                      | 질문                                   | 대표 contract / owner                                                                                    | 해석                                                                                                       |
| ----------------------- | -------------------------------------- | -------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| Public target relation  | viewer와 target의 관계는 무엇인가?     | `relation.type = GENERAL                                                                                 | MATCHED_PARTNER`                                                                                           | `GENERAL`은 matched partner가 아닌 registration complete public target이고, `MATCHED_PARTNER`는 이미 형성된 매칭 결과 context다 |
| Exposure level          | target을 어디까지 볼 수 있는가?        | `exposure.listSummaryVisible`, `exposure.detailViewable`/`exposure.canViewFull`, `exposure.scoreVisible` | list-summary/detail/score 노출 수준이다. `summary`는 FE 카드가 아니라 API/read-model의 최소 projection이다 |
| Action capability       | 지금 새 행동을 할 수 있는가?           | `actions.canBookmark`, `actions.canRequestMatch`, `actions.canStartChat`, current-user write capability  | bookmark/match/chat/profile/dormitory write 가능 여부다                                                    |
| Result-read context     | 이미 만들어진 결과·관계·이력을 읽는가? | `resultRead.context`, match history owner, chat thread owner, matched partner detail                     | 신규 action 가능 여부와 별도이며, past/current result row를 읽는 맥락이다                                  |
| Read-only storage state | 저장 모델이 쓰기 잠김 상태인가?        | `ConversationThread.status = READ_ONLY`, registration 이후 final/read-only profile                       | chat thread status 또는 profile write lock이다. `summary-only`와 같은 계층이 아니다                        |

따라서 `summary-only`는 “list-summary exposure만 가능하고 detail/score가 닫힘”을 뜻한다. `action-closed`는 match/chat/profile write command가 닫힌 상태를 뜻한다. `result-read`는 이미 형성된 match/thread/history 결과를 읽는 맥락이다. 세 축은 함께 조합될 수 있지만 서로를 대체하지 않는다.

| capability                                         | 의미                                                                                              | owner                      |
| -------------------------------------------------- | ------------------------------------------------------------------------------------------------- | -------------------------- |
| `exposure.listSummaryVisible`                      | roommate-search summary card를 볼 수 있는지                                                       | search/exposure owner      |
| `exposure.detailViewable` / `exposure.canViewFull` | profile detail API를 열 수 있는지                                                                 | profile detail owner       |
| `exposure.scoreVisible`                            | summary/detail에 `matchScore`를 포함할 수 있는지                                                  | match score exposure owner |
| `actions.canBookmark`                              | same-dormitory candidate bookmark 가능 여부. 다른 dormitory 또는 result-only target에는 열지 않음 | matching/search owner      |
| `actions.canRequestMatch`                          | match request CTA 가능 여부                                                                       | match owner                |
| `actions.canStartChat`                             | chat UI entry / first message 가능 여부                                                           | chat owner                 |

Summary card는 detail 가능 여부와 무관하게 동일 field set을 사용한다. 미등록 viewer도 시즌 기간에는 registration 완료 target의 summary card를 볼 수 있지만, score/detail/match/chat action은 닫힌다.

Target cohort는 `SeasonParticipant`를 root로 하며, registration 전 draft profile은 public target이 아니다. Hidden/deactivated/deleted participant는 summary/detail/action capability에서 제외한다.

`canEnterRoommateSearch`는 검색 탭 진입 가능 여부를 나타내는 coarse capability다. Summary scope 사용 가능 여부는 roommate-search response의 `scopeAvailability`가 표현하고, detail/score 가능 여부와 match/chat CTA는 search item capability와 각 domain owner의 action precondition을 따른다.

`SEASON_MATCHING`에서 registration 완료 + `ASSIGNED` viewer는 같은 dormitory action boundary와 정합성을 맞추기 위해 `SAME_BUILDING_ONLY` summary/detail cohort를 사용한다. 미등록 또는 selection-required viewer의 `CAMPUS_MERGED` browse는 summary-only exposure이며, match/chat action capability를 열지 않는다. `SEASON_POST_MATCH`는 신규 action이 닫힌 result period이므로 registration 완료 viewer도 기본 summary scope가 `CAMPUS_MERGED`다. 다만 registration 완료 + `ASSIGNED` viewer가 같은 기숙사 season cohort를 회고/확인하는 `SAME_BUILDING_ONLY` scope를 요청할 수 있으며, 이 scope는 신규 후보 discovery가 아니므로 active matched target을 포함하되 filter/score/action은 열지 않는다.

Roommate-search의 `ACTIONABLE_DETAIL_DISCOVERY` purpose는 신규 후보 discovery surface이므로 active matched target을 list에서 제외한다. `POST_MATCH_COHORT_REVIEW` purpose는 신규 후보 탐색이 아니므로 같은 제외 규칙을 적용하지 않는다. Active matched partner detail/score, existing thread, past final matched history는 search list가 아니라 각 도메인의 result-read/context owner가 처리한다. 정상 search summary entry에서 detail로 진입할 때는 서버가 발급한 `detailEntryToken`으로 entry context를 확인하고, full detail이 불가능하면 tombstone shell로 안내할 수 있다. Token이 없거나 위조/만료되면 direct/probing 접근으로 간주해 fail-closed한다.

### 자기 시즌 등록 준비 작업의 계층

“자기 시즌 등록 준비 작업”은 public target exposure/action과 다른 계층이다. 이는 내가 타인을 볼 수 있는지가 아니라, **내 current season participant aggregate를 registration 전까지 작성·완성·확정할 수 있는가**를 판단한다.

| 축                               | owner                            | 예                                                                                                                                        | public target capability와의 관계                                                                                            |
| -------------------------------- | -------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| Registration preparation write   | season-participants              | season profile draft 작성, dormitory selection draft 저장                                                                                 | registration 전 `SEASON_OPEN`/`SEASON_MATCHING`에서만 가능. 타인 summary/detail 권한과 별도                                  |
| Registration preparation display | current-user/account identity    | 준비 UI에서 닉네임은 `CurrentUserResponse.displayIdentity`, 단과대/출생연도는 `CurrentUserResponse.academicIdentity`를 표시 source로 사용 | `SeasonProfileDraftResponse`는 lifestyle/condition/intro/season additional draft만 소유하며 account identity를 포함하지 않음 |
| Registration finalize            | season-participants              | complete profile + valid saved dormitory selection을 `REGISTERED + ASSIGNED`로 확정                                                       | finalize 이후 public target cohort에 들어갈 수 있음                                                                          |
| Post-registration self lock      | season-participants              | registration 이후 season profile/dormitory selection write lock                                                                           | 내가 public target이 되는 전제이며, 타인 action capability를 자동으로 열지는 않음                                            |
| Public target action/read        | search/match/chat/profile owners | bookmark/match request/chat/detail/score                                                                                                  | registration complete 이후에도 same dormitory, season phase, active match, cutoff, safety 상태를 추가로 봄                   |

따라서 미등록 사용자가 `SEASON_OPEN`/`SEASON_MATCHING`에서 profile draft와 dormitory selection을 저장할 수 있어도, 이는 “타인에게 action 가능”을 뜻하지 않는다. 반대로 registration 완료 사용자는 자기 registration 준비 write가 잠기지만, 타인 summary/detail/action은 별도 capability owner가 판단한다.

## 시즌 참여자 등록의 의미

시즌 참여자 registration finalize는 아래 의미를 함께 가진다.

1. 이번 시즌에 참여하겠다는 명시적 의사 표시
2. complete lifestyle/condition, account `UserAcademicIdentity(collegeCode, birthYear)`, season additional `grade`/full `mbti`를 registration snapshot으로 고정
3. registration 전 저장된 유효한 기숙사 선택 draft를 `ASSIGNED`로 확정
4. `registeredAt`과 `SeasonParticipantProfileHistory(source = SEASON_REGISTRATION, registeredAtSnapshot)`를 같은 transaction에서 남김
5. public summary/search, match score, match/chat capability의 계산 대상이 됨

다만 registration 완료가 곧바로 모든 action 가능을 뜻하지는 않는다. 동일 dormitory/gender/campus, season phase, `roomSelectionDate`, active match/read-only thread, safety/hidden 상태 같은 추가 조건을 각 owner가 본다.

- 매칭 요청 가능 여부: [matching-lifecycle.md](./matching-lifecycle.md)
- 채팅 가능 여부: [chat-lifecycle.md](./chat-lifecycle.md)
- 검색 summary/detail/score: [roommate-searching.md](./roommate-searching.md)
- 필드 구조와 snapshot: [profile-model.md](./profile-model.md)
