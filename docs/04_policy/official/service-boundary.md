# 서비스 책임 범위 정책

## 문서 범위

이 문서는 서비스가 어디까지 제공하고, 무엇을 보장하지 않으며, 분쟁 시 어떤 수준까지 개입하는지를 다룬다.

상태 전이와 수치 규칙은 [matching-lifecycle.md](./matching-lifecycle.md)가 최종 소유한다.

## 서비스 기능 범위

| 항목             | 정책                                     |
| ---------------- | ---------------------------------------- |
| 핵심 기능        | 프로필 탐색, 호환도 계산, 매칭, 1:1 채팅 |
| 채팅 방식        | 실시간 채팅 + 메시지 영속성              |
| 서비스 종료 시점 | 시즌 종료 시 일괄 종료                   |
| 학교 시스템 연동 | 하지 않음                                |

채팅은 선택 기능이 아니라 핵심 범위에 포함된다.
프로필만 보고 바로 확정시키지 않고, 대화 후 확정하도록 설계한다.

## 서비스가 보장하는 것과 보장하지 않는 것

| 영역                  | 정책          |
| --------------------- | ------------- |
| 생활패턴 기반 탐색    | 제공          |
| 서비스 내 대화        | 제공          |
| 호실 선택 성공        | 보장하지 않음 |
| 프로필 진실성         | 보장하지 않음 |
| 외부 채널 결과        | 보장하지 않음 |
| 학교 시스템 일정/권한 | 보장하지 않음 |

## 시스템 미확정

서비스 밖에서 연락처를 교환하고 실제 합의했더라도,
서비스 내 `매칭 확정`을 누르지 않으면 아래 보호는 적용되지 않는다.

| 보호 항목     | 적용 조건                |
| ------------- | ------------------------ |
| 잠금 상태     | 서비스 내 확정 완료      |
| 취소 프로세스 | 서비스 내 확정 완료      |
| 관계 정리     | 서비스 내 상태 전이 기준 |

대응 원칙은 `리마인더 + 면책 안내`다.

## 면책 범위

| 영역               | 면책 수준 | 비고                                                                               |
| ------------------ | --------- | ---------------------------------------------------------------------------------- |
| 프로필 진실성      | 면책      | 자기 신고 기반                                                                     |
| 매칭 만족도        | 면책      | 생활패턴 호환성이 만족을 보장하지 않음                                             |
| 호실 선택 성공     | 완전 면책 | 학교 시스템 영역                                                                   |
| 채팅 내 위반 행위  | 부분 면책 | 신고/제재/수사 협조는 수행                                                         |
| 매칭 이탈          | 면책      | 운영 규칙에 따라 처리                                                              |
| 외부 소통 결과     | 완전 면책 | 서비스 밖 영역                                                                     |
| 시스템 미확정      | 면책      | 서비스 내 확정 전제 미충족                                                         |
| 생활패턴 설문 내용 | 면책      | 설문 항목은 생활 호환성 파악 목적이며, 학교 기숙사 규정상 허용행위를 의미하지 않음 |

## 면책 고지 시점

| 시점                               | 원칙                                              |
| ---------------------------------- | ------------------------------------------------- |
| 서비스 진입 (랜딩/로그인/회원가입) | 학교 공식 서비스가 아닌 독립 운영 서비스임을 고지 |
| 가입                               | 약관으로 고지                                     |
| 매칭 신청                          | 추천은 호환도 참고용임을 고지                     |
| 매칭 확정                          | 호실 선택은 학교 시스템에서 직접 진행함을 고지    |
| 채팅 진입                          | 개인정보 공유 주의를 고지                         |

## 악의적 사용 대응 원칙

| 수준 | 의미           | 상세 정책                                            |
| ---- | -------------- | ---------------------------------------------------- |
| L0   | 구조적 방지    | —                                                    |
| L1   | UX 방지턱      | —                                                    |
| L2   | 사후 피드백    | —                                                    |
| L3   | 신고 기반 제재 | [incident-enforcement.md](./incident-enforcement.md) |
| L4   | 법적 대응 지원 | [incident-enforcement.md](./incident-enforcement.md) |

### 운영 원칙

1. 구조적 자정이 1차 방어선이다.
2. 판별 불가한 사안은 무리한 징벌보다 피드백을 우선한다.
3. 제재는 경중 비례로 적용한다.
4. 성별 사칭은 무관용으로 다룬다.
5. 실행 가능한 경고만 사용한다.

## 분쟁 시 서비스 역할

### 역할 수준

| 분쟁 유형                                     | 서비스 역할                |
| --------------------------------------------- | -------------------------- |
| 서비스 밖 분쟁                                | 관여 안 함                 |
| 채팅 위반 / 프로필 불일치                     | 기계적 처리 또는 누적 제재 |
| 취소 교착 / 노쇼 / 성별 사칭 / 형사 수준 행위 | 관리자 개입                |

### 관리자 모델

| 하는 것        | 하지 않는 것 |
| -------------- | ------------ |
| 증거 확인      | 화해 중재    |
| 규정 위반 판단 | 도덕적 심판  |
| 제재 실행      | 피해 보상    |
| 수사기관 협조  | 법적 자문    |

## 수사기관 협조

| 항목      | 정책              |
| --------- | ----------------- |
| 협조 조건 | 적법한 요청       |
| 제공 대상 | 관련 채팅 로그 등 |
| 약관 반영 | 명시적으로 포함   |

## RRPD retained vault 접근 경계

서비스는 일반 사용자에게 삭제 사용자의 retained payload를 복원해 제공하지 않는다. 계정 삭제 후 과거 매칭 상대, 채팅 상대, 프로필 이력은 `탈퇴한 사용자`/minimal summary/tombstone으로 표현하며, `RetainedVaultObject`의 원문 payload는 product application read path, realtime event, cache, search/detail API의 source가 아니다.

관리자·운영자도 retained vault payload를 무제한 조회하지 않는다. 신고/분쟁/제재/수사기관 협조 등 명확한 목적이 있는 경우에만 approval reference와 access log를 남기는 별도 disclosure workflow를 사용한다. 서비스의 역할은 분쟁 해결 자체가 아니라 서비스 내 증거 확인, 규정 위반 판단, 제재 실행, 적법한 요청에 대한 협조로 제한된다.

DB credential 경계도 서비스 책임에 포함한다. 일반 API runtime은 retained payload/identifier payload를 직접 조회하지 못해야 하며, archive/disposal/review는 retention worker credential, 승인 disclosure는 retention disclosure credential로 분리한다. 이 분리는 운영자 UI 존재 여부와 무관한 BE/DB 안전 경계다.

각 domain의 source row 의미와 사용자-facing 최소화 규칙은 해당 owner domain이 소유한다. Retention boundary는 제한 보존 queue, vault, case, disclosure, access log, review/disposal 경계를 제공하지만, 일반 product API가 retained payload를 복원하거나 외부 domain semantics를 우회하는 통로가 아니다.

운영 관측은 retained payload를 노출하지 않는 구조화 signal만 남긴다. manual review, retry exhaustion, key unavailable, disposal/review backlog, sweep latency는 운영자가 감지해야 하는 상태지만, product application 사용자에게 retained payload를 복원하거나 공개하는 근거가 되지 않는다.
