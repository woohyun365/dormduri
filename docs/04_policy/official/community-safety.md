# 커뮤니티 안전 정책

## 문서 범위

이 문서는 공개 텍스트에 대한 moderation, 개인정보 노출 가이드, 소수자 포용 원칙을 다룬다.

- 서비스 책임 범위와 제재 수준: [service-boundary.md](./service-boundary.md)
- 신고 카테고리, 제재 사다리, 증거 판단, 임시조치: [incident-enforcement.md](./incident-enforcement.md)
- 닉네임 구조/변경 규칙: [profile-model.md](./profile-model.md)

## 적용 대상

타인에게 보이는 모든 텍스트 입력 영역에 적용한다.

| 영역                   | 정책                                                                        |
| ---------------------- | --------------------------------------------------------------------------- |
| 닉네임                 | 사전 차단                                                                   |
| season profile `intro` | 사전 차단                                                                   |
| 매칭 요청 note         | 사전 차단                                                                   |
| 채팅                   | 실시간 입력 차단은 하지 않고 사후 대응 중심. read-only 상태에서도 신고 가능 |

## 텍스트 moderation 원칙

### 3단계 방어

| 단계 | 정책                   |
| ---- | ---------------------- |
| 1차  | 서버 저장 전 사전 필터 |
| 2차  | 사용자 신고            |
| 3차  | 누적 제재              |

프론트는 실시간 필터 사전을 갖지 않고, 서버 결과를 표시하는 구조를 기본으로 한다.

### 금지어 범주

| 범주        | 예시                           |
| ----------- | ------------------------------ |
| 일반 비속어 | 시발, 씨발, 개새끼, 병신, 지랄 |
| 성적 비속어 | 보지, 자지, 섹스, 야동         |
| 혐오 표현   | 한남, 한녀, 맘충, 틀딱         |
| 차별 표현   | 장애인 비하어, 인종 비하어     |
| 자모 축약   | ㅅㅂ, ㅆㅂ, ㅅㅅ               |

### 우회 대응 수준

| 수준              | 정책       |
| ----------------- | ---------- |
| Lv.1 기본 사전    | 적용       |
| Lv.2 정규화       | 적용       |
| Lv.3 키보드 치환  | 적용 안 함 |
| Lv.4 AI 맥락 판정 | 적용 안 함 |

### 맥락 중심 판단 원칙

단어 자체를 금지하는 것이 아니라, 맥락·배제·괴롭힘·반복성을 기준으로 판단한다.

| 원칙             | 설명                                                         |
| ---------------- | ------------------------------------------------------------ |
| 단어 자체 불금지 | 민감 용어(`게이`, `장애인` 등)는 금지어 목록에 포함하지 않음 |
| 맥락 기반 판단   | 동일 단어라도 자기 표현과 타인 배제는 다르게 취급            |
| 신고 기반 처리   | 혐오 맥락은 자동 필터가 아닌 신고 → 제재로 대응              |
| 반복성 고려      | 단발 표현과 반복적 괴롭힘은 제재 수준이 다름                 |

## 제재 방식

| 영역                   | 정책                                    |
| ---------------------- | --------------------------------------- |
| 닉네임                 | 입력 차단 또는 제재 시 임시 닉네임 대체 |
| season profile `intro` | 입력 차단 또는 초기화                   |
| 매칭 요청 note         | 입력 차단 또는 저장 거부                |
| 채팅                   | 사후 신고/제재                          |

### 닉네임 제재 특칙

| 항목           | 정책                       |
| -------------- | -------------------------- |
| 제재 시 닉네임 | 임시 닉네임으로 대체       |
| 탐색 노출      | 강제 수정 전까지 제외 가능 |
| 변경 주기 예외 | 30일 제한 예외 허용        |

## 신고 접수 후 보호 조치

| 구분                        | 정책                                     |
| --------------------------- | ---------------------------------------- |
| 고위험 신고                 | 즉시 보호 조치 또는 thread 비활성화 가능 |
| 일반 신고                   | 관리자 판단 후 상태 변경                 |
| read-only / inactive thread | 신고 가능                                |

채팅 thread의 즉시 차단/비활성화 여부는 신고의 위험도에 따라 다르게 판단한다. 일반 신고는 관리자 검토를 우선하고, 위협·성희롱 등 고위험 신고는 즉시 보호 조치를 허용한다.

## 신고/차단/문의/알림 product baseline

| 기능           | 안전 정책                                                                                                                | owner 문서                                             |
| -------------- | ------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------ |
| 신고           | 사용자 간 interaction에는 신고 경로를 제공한다. intake만으로 숨김/정지를 수행하지 않고 운영 검토/decision으로 분리한다   | [incident-enforcement.md](./incident-enforcement.md)   |
| 차단           | viewer-specific relation이다. 상대에게 차단 사실을 직접 고지하지 않고 리스트/요청/비매칭 thread를 fail-closed로 정리한다 | [matching-lifecycle.md](./matching-lifecycle.md)       |
| 북마크         | 안전 기능은 아니지만 block create 시 양방향 active bookmark 제거 대상이다                                                | [matching-lifecycle.md](./matching-lifecycle.md)       |
| 문의/이의 신청 | 신고 처리, 제재, 계정/시즌 문제는 support ticket으로 문의할 수 있다                                                      | [support-communication.md](./support-communication.md) |
| 알림           | 신고/지원/운영 알림은 in-app notification이 primary다. Push는 MVP 제외                                                   | [notification-inbox.md](./notification-inbox.md)       |

## 개인정보 노출 정책

### 기본 원칙

| 구분                    | 정책          |
| ----------------------- | ------------- |
| 본인 연락처 자발적 노출 | 권장하지 않음 |
| 타인 개인정보 노출      | 금지          |

서비스는 season profile `intro`와 매칭 요청 note에서 연락처를 기계적으로 모두 차단하지 않는다.
대신 helper 안내와 신고/제재 구조를 사용한다. `messageToRoommate`/“룸메에게 한마디”는 더 이상 별도 profile field가 아니다.

### 적용 방식

| 방식          | 정책                                                    |
| ------------- | ------------------------------------------------------- |
| Helper 안내   | season profile `intro`, 매칭 요청 note에 상시 표시 가능 |
| 자동 탐지     | 기본 도입 안 함                                         |
| 신고 카테고리 | 개인정보 노출 포함                                      |

### 민감 용어와 민감정보 구분

| 구분      | 정의                                                                                          | 예시                                      | 정책                               |
| --------- | --------------------------------------------------------------------------------------------- | ----------------------------------------- | ---------------------------------- |
| 민감 용어 | 맥락에 따라 자기 표현일 수 있는 단어                                                          | `게이`, `장애인`, `트랜스젠더`            | 금지어 목록 미포함. 맥락 중심 판단 |
| 민감정보  | 개인정보보호법 제23조상 민감정보(건강, 성생활 등) 또는 그에 준하는 사생활 침해 우려가 큰 정보 | 건강 상태, 성생활, 장애 여부 등 사실 자체 | 자기노출 주의 안내                 |

민감 용어를 사용했다고 해서 민감정보를 노출한 것은 아니다.
"게이 룸메 구합니다"는 자기 표현이지, 타인의 민감정보를 노출하는 것이 아니다.

### 민감정보 자기노출 주의

| 구분      | 정책                                                      | 근거                                |
| --------- | --------------------------------------------------------- | ----------------------------------- |
| 기본 원칙 | 권장하지 않음 (안내 + 사용자 판단에 일임)                 | 개인정보보호법 제23조               |
| 안내 방식 | season profile `intro`/매칭 요청 note 입력 시 helper 안내 | 기존 연락처 노출 안내와 동일 패턴   |
| 차단 여부 | 자동 차단하지 않음                                        | 자기 표현 경로 보장                 |
| 채팅      | 최초 진입 시 주의 안내                                    | 기존 개인정보 공유 주의 고지와 통합 |

helper 안내 예시: "건강, 장애, 성적 지향 등 민감한 개인정보는 신중하게 공유해 주세요."

## 소수자 포용 원칙

### 서비스 입장

| 항목           | 정책                                  |
| -------------- | ------------------------------------- |
| 기본 원칙      | 성적 지향을 구조화 필드로 다루지 않음 |
| 자기 표현      | 허용                                  |
| 타인 배제 표현 | 신고 → 제재                           |
| 구조화 필드    | 제공하지 않음                         |

### 표현 기준

| 표현 유형        | 정책          | 예시                                |
| ---------------- | ------------- | ----------------------------------- |
| 자기 표현        | 허용          | `저 게이에요`, `게이 룸메 구합니다` |
| 타인 배제        | 제재 대상     | `게이 사절`, `동성애자 싫음`        |
| 거절의 내심 동기 | 판단하지 않음 | 거절 사유 미수집                    |

### 민감 용어 예시

| 카테고리  | 용어                                           |
| --------- | ---------------------------------------------- |
| 성적 지향 | 게이, 레즈비언, 동성애자, 바이, 양성애자, 퀴어 |
| 성 정체성 | 트랜스젠더, 논바이너리                         |
| 기타      | 장애인, 다문화, 외국인                         |

위 용어는 금지어 목록에 포함하지 않는다.

### 시나리오별 처리

| 시나리오                           | 처리                    | 근거                                                   |
| ---------------------------------- | ----------------------- | ------------------------------------------------------ |
| "저 게이에요" 자기소개             | 허용                    | 자기 표현. 민감 용어 허용 정책                         |
| "게이 룸메 구합니다"               | 허용                    | 자기 표현 + 선호 표현                                  |
| "게이 사절"                        | 신고 → 제재             | 특정 성적 지향 배제 표현 금지                          |
| 성적 지향 이유로 거절              | 판단 불가 (사유 미수집) | 거절 시 사유 입력 없음. 내심 동기는 서비스가 관여 불가 |
| 매칭 후 성적 지향 발견 → 해제 요청 | 양측 동의 취소          | 기존 취소 정책과 동일. 사유 불문                       |
| "게이 룸메 구합니다"를 신고        | 제재 대상 아님          | 자기 표현 범위. 혐오 맥락 아님                         |
| 성적 지향 혐오 채팅                | 신고 → 제재             | 서비스 약관 위반                                       |

### 원칙

1. 서비스 핵심은 생활패턴 호환성이다.
2. 성적 지향 구조화 필드는 차별 필터로 악용될 위험이 있다 (필터링 도구화 방지).
3. 자기소개 텍스트는 자기 표현 경로로 충분하다.
4. 자기 표현과 타인 배제는 다르게 취급한다.
5. 거절 사유를 수집하지 않으므로, 거절의 내심 동기는 판단하지 않는다.
