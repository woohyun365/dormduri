[Review criteria](./README.md)의 `web-be-authn-authz` 기준입니다. Server 진입점의 기본 인증과 판정 위치, role·capability·운영자
권한과 진입점별 인가 표를 더하거나 바꾸는 변경에 적용합니다.

이 문서를 고르면 [`swe`](./swe.md)와 상속하는 security-privacy 항목
[web-security-privacy-trust-authz-model.md P2](./web-security-privacy-trust-authz-model.md#p2-서버-쪽-인가와-객체-단위-권한)·[web-security-privacy-trust-authz-model.md P3](./web-security-privacy-trust-authz-model.md#p3-열거추측재전송빈도-남용-방어)도
함께 고릅니다. 이 문서의 항목은 상속 항목보다 좁은 조건을 더 봅니다. 강화 관계는 E1 → [swe.md S4](./swe.md#s4-책임-경계와-결합도), E2 →
[swe.md S2](./swe.md#s2-제품-정책-부합)입니다.

각 항목의 지침·피함은 구현할 때 보는 보기이고, 나머지 줄은 리뷰할 때 보는 보기입니다. 적용 조건은 두 보기가 함께 씁니다.

### E1. 기본 인증과 공통 판정 위치

- 질문: 새 진입점이 기본으로 인증을 요구하고 공개 진입점만 명시적으로 표시하며, 인증 판정을 진입점마다 복사하지 않고 공통 판정 위치에 두는가?
- 기본 severity: `high`
- 적용 조건: 새 진입점을 더하거나 인증·인가 판정 code를 바꾸는 변경
- 결함 패턴: 새 진입점이 기본으로 공개됨(인증을 하나씩 켜는 방식), 진입점마다 인증 판정을 손으로 복사함, 판정이 business code 안에 흩어져 빠진 경로가 생김
- PASS 근거: 전역 기본 보호와 공개 표시가 source에 있고, 모든 진입점의 인증 요구 여부를 나열한 test(진입점 인증 matrix)가 새 진입점을 포함하며, 공개 표시가 없는 진입점이 인증 없는 요청을 거부한다
- 지침: 인증은 진입점 공통 판정에서 기본으로 켜고 공개 진입점만 표시로 연다. 판정은 공통 위치에 두고 업무 code 안에 흩지 않는다. 공개 진입점이 많아도 기본 보호를 유지하고 공개 표시를 늘린다
- 피함: 진입점마다 인증을 하나씩 켜기, 판정 code 복사하기, 업무 code 안에 인증 판정 흩기

### E2. capability·role 판정과 진입점별 인가 표

- 질문: role·capability·운영자 권한 판정이 진입점별 인가 표(누가 무엇을 할 수 있는가)와 code·test에서 같고, 역할 밖 조건(상태·소유)을 보는 판정을 역할 이름만으로 대신하지 않으며, 운영자 권한의 부여·사용이 감사 기록을 남기는가?
- 기본 severity: `medium`
- 적용 조건: role·capability·운영자 권한을 더하거나 바꾸는 변경
- 결함 패턴: 역할 이름만으로 판정해 capability와 어긋남, 진입점별 인가 표(누가 무엇을 할 수 있는가)가 code·test와 다름, 운영자 권한의 부여·사용이 감사 기록 없이 일어남
- PASS 근거: 진입점별 인가 표가 정책 원본이나 owner 문서에 있고 표의 행마다 허용·거부 test가 있으며 거부 test에 다른 사용자의 자원 id로 접근하는 경우가 들고, 운영자 권한의 부여·사용에 감사 기록 test가 있다. 화면이 행동 가능 여부를 미리 보여 주고 server 판정이 역할 밖 조건을 보면, 그 값을 역할로 계산하지 않고 server가 계산해 준다
- 지침: 진입점마다 누가 무엇을 할 수 있는지 인가 표로 적고 code·test를 그 표에 맞춘다. 화면이 행동 가능 여부를 미리 보여 주는데 server가 역할 밖 조건(상태·소유)으로 판정하면, 화면 값은 server가 계산해 응답에 담는다. 운영자 권한은 부여와 사용을 감사 기록으로 남긴다
- 피함: 역할 밖 조건을 보는 판정을 역할 이름만으로 하기, code·test와 다른 인가 표, 감사 기록 없는 운영자 권한
