# Web FE design system criteria

[Review criteria](./README.md)의 `web-fe-design-system` 기준입니다. Web frontend에서 design token 사용, 공통 UI 부품의
재사용·승격, 화면 문구의 원본을 바꾸는 변경에 적용합니다. 색·간격 같은 시각 값 자체와 미감 판정은 이 문서에 두지 않습니다.

이 문서를 고르면 [`swe`](./swe.md)도 함께 고릅니다. 이 문서의 항목은 `swe` 항목을 상속하고 강화만 합니다. 강화 관계는 F1 →
[swe.md S11](./swe.md#s11-응집도와-중복-trade-off), F2 → [swe.md S4](./swe.md#s4-책임-경계와-결합도), F3 →
[swe.md S2](./swe.md#s2-제품-정책-부합)입니다.

각 항목의 지침·피함은 구현할 때 보는 보기이고, 나머지 줄은 리뷰할 때 보는 보기입니다. 적용 조건은 두 보기가 함께 씁니다.

### F1. semantic token만 사용

- 질문: style이 raw 값 대신 의미 이름의 token을 쓰고, token의 의미와 값이 한 곳에서 정해지는가?
- 기본 severity: `medium`
- 적용 조건: 색·간격·글꼴·그림자·모서리·쌓임 순서를 쓰거나 token을 더하는 style 변경
- 결함 패턴: raw 색·크기 값이나 도구의 기본 palette를 화면에 직접 씀, 의미 대신 값 이름(색 이름 등)으로 token을 만듦, theme·override를 화면마다 따로 처리함, 같은 의미의 token이 둘 생김
- PASS 근거: 바뀐 style이 semantic token만 참조하고 새 token은 token 원본에 의미 이름으로 있다. raw 값 금지 검사가 있으면 통과한다
- 지침: style은 semantic token으로만 쓰고, 필요한 의미가 없으면 token 원본에 의미 이름으로 먼저 더한다. 값은 token 원본 한 곳에서 정한다
- 피함: 화면에서 raw 값 쓰기, 값 이름의 token, 화면별 theme 분기

### F2. 부품 재사용과 승격

- 질문: 공통 UI 부품이 있으면 그것을 쓰고, 새 공통 부품은 승격 조건을 거쳐 올리는가?
- 기본 severity: `low`
- 적용 조건: button·입력·dialog 같은 공통 UI 부품을 쓰거나 더하는 변경
- 결함 패턴: 있는 공통 부품 대신 같은 역할 부품을 새로 만듦, 한 화면에서만 쓰는 부품을 공통 부품으로 올림, 공통 부품을 화면 요구에 맞춰 option으로 계속 넓힘
- PASS 근거: 새 부품마다 기존 공통 부품 검색 결과가 있고, 승격한 부품은 두 곳 이상에서 같은 의미·상호작용·상태 계약으로 쓰인다
- 지침: 공통 부품을 먼저 찾아 쓰고 화면 부품은 화면 owner에 둔다. 두 곳 이상에서 같은 의미·상호작용·상태 계약이 확인되면 공통 부품으로 올린다
- 피함: 비슷한 부품 새로 만들기, 성급한 승격, 공통 부품에 화면 전용 option 더하기

### F3. 사용자 문구 권한

- 질문: 화면 문구가 말하는 제품 사실·정책·상태·수치가 승인된 원본에서 오는가?
- 기본 severity: `medium`
- 적용 조건: 화면 문구·안내·오류 문구·법적 고지를 더하거나 바꾸는 변경
- 결함 패턴: 참고 디자인·초안의 예시 문구로 제품 사실·정책·수치를 만들어 냄, 정책 원본 없이 기한·권한·공개 범위를 문구로 약속함, 같은 사실을 화면마다 다른 문구로 씀
- PASS 근거: 사실·정책을 말하는 문구마다 정책 원본이나 승인된 content 원본 위치가 있고, 문구가 그 원본을 참조한다
- 지침: 정책·법적 사실 문구는 정책 원본에서, 나머지는 승인된 content 원본에서 가져온다. 원본이 없으면 문구를 지어내지 않고 승인을 받는다
- 피함: 임시 문구로 사실을 발명하기, 같은 문구를 화면마다 직접 쓰기
