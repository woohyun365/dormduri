# Document review criteria

[Review criteria](./README.md)의 `documents` 기준입니다. Tracked 문서·plan·evidence가 규칙, 사실, 수치, 근거를 바꿀 때
적용합니다. 문서 리뷰에서 가장 중요한 것은 정합성입니다. 문서가 실제 동작·다른 owner 문서·자기 자신과 같은 말을 해야 합니다.

### D1. 문서와 동작의 일치

- 질문: 문서가 설명하는 동작·명령·기본값·거부 조건이 현재 code·test·설정과 같은가?
- 기본 severity: `medium`
- 적용 조건: 문서가 script·CLI·hook·설정·제품 동작을 설명하거나 바꾸는 변경
- 결함 패턴: 코드가 바뀐 뒤 문서의 옵션·순서·거부 사유가 이전 동작을 설명함, 문서가 강제한다고 쓴 규칙이 실제로는 advisory임
- PASS 근거: 문서가 설명하는 동작마다 그 동작을 정하는 code·test·설정 위치가 있고, 옵션·순서·거부 사유 이름이 그 위치와 같다
- 지침: 동작을 바꾸면 그 동작을 설명하는 문서를 검색해 같은 변경에서 고친다. 강제 강도(결정적 검사·지침·runtime 강제)를 실제 owner에 맞게 쓴다
- 피함: 기억이나 이전 문서로 동작을 설명하기, advisory 규칙을 강제된 것처럼 쓰기

### D2. 근거 참조의 현재성

- 질문: 규칙이나 주장의 근거로 인용한 경로·`path:line`·anchor·문서 이름이 현재 source에서 그 내용을 가리키는가?
- 기본 severity: `medium`
- 적용 조건: 판정·규칙·수치의 근거로 쓰인 참조. 근거가 아닌 안내 링크는 `low`
- 결함 패턴: 파일 이동·편집 뒤 줄 번호가 다른 내용을 가리킴, 옮겨진 문서를 옛 경로로 인용함
- PASS 근거: 근거 참조가 인용 검사를 통과하고, 줄 번호 인용은 내용 대조나 runner 기록으로 그 내용을 가리킴이 보인다
- 지침: 근거는 현재 source에서 다시 열어 확인한 경로·줄로 쓰고, 편집으로 줄이 밀리면 함께 고친다
- 피함: 옛 경로·줄 번호를 확인 없이 재사용하기, 안내 링크를 판정 근거처럼 쓰기

### D3. 단일 원본과 내부 일관성

- 질문: 같은 규칙·수치·순서를 이 변경 안의 여러 곳이나 다른 owner 문서가 서로 다르게 말하지 않는가?
- 기본 severity: `medium`
- 적용 조건: 규칙·수치·순서·범위를 정하거나 고치는 변경
- 결함 패턴: 한 절만 고쳐 같은 문서의 다른 절·표와 어긋남, owner가 아닌 문서가 규칙을 다시 써서 원본과 갈라짐
- PASS 근거: 바뀐 규칙·수치·순서를 저장소 전체에서 검색한 기록이 있고, 같은 서술이 owner 한 곳에만 있거나 나머지가 owner를 링크한다
- 지침: 규칙을 바꾸기 전에 같은 규칙을 말하는 문서·절·표를 검색하고, owner를 고친 뒤 나머지는 링크로 맞춘다
- 피함: owner가 아닌 문서에 규칙을 다시 쓰기, 한 절만 고치고 같은 문서의 다른 절·표를 그대로 두기

### D4. 이관·요약의 의미 보존

- 질문: 규칙을 옮기거나 줄이거나 바꿔 쓸 때 조건·예외·강도(필수/권장)가 그대로인가?
- 기본 severity: `medium`
- 적용 조건: 문서 이동·분할·통합·요약·용어 정리
- 결함 패턴: 이관 중 예외 조건이 빠지거나 권장이 필수로 바뀜, 요약이 원문보다 넓은 범위를 주장함
- PASS 근거: 옮기거나 줄인 규칙마다 원문과 결과의 조건·예외·강도를 대조한 기록이 있다
- 지침: 이관 전에 원문의 조건·예외·강도를 목록으로 만들고 결과에서 하나씩 확인한다
- 피함: 요약하며 예외 빼기, 권장과 필수의 강도 바꾸기, 원문보다 넓은 범위로 일반화하기

### D5. 증거가 주장을 넘지 않음

- 질문: 완료·수치·효과 주장이 실제로 실행·관측한 증거의 범위 안에 있는가?
- 기본 severity: `medium`
- 적용 조건: 검증 결과, 측정값, 완료 상태, 효과를 주장하는 변경
- 결함 패턴: 일부 실행으로 전체 통과를 주장함, 기록된 건수와 실제 실행 건수가 다름, 공급사 자체 보고를 독립 근거처럼 씀
- PASS 근거: 완료·수치·효과 주장마다 그것을 낳은 실행 기록(명령·exit·출력)이 있고 주장 범위가 그 실행 범위 안이다
- 지침: 주장은 실제 실행한 명령과 출력에서 옮겨 쓰고, 실행하지 못한 범위는 검증 공백으로 적는다
- 피함: 일부 실행으로 전체 통과를 쓰기, 다시 실행하지 않은 기억 속 수치 쓰기, 공급사 자체 보고를 독립 근거로 쓰기

### D6. 입력 목록과 분류의 근거

- 질문: 영향 목록·대상 목록·분류가 이름이 아니라 내용 확인과 재현 가능한 검색으로 만들어졌는가?
- 기본 severity: `medium`
- 적용 조건: 영향 범위, 대상 파일 목록, 분류, 계획 입력을 정하는 변경
- 결함 패턴: 파일 이름만 보고 분류해 다른 성격의 파일이 섞임, 영향 목록이 일부 caller를 빠뜨림
- PASS 근거: 목록·분류마다 재현 가능한 검색 명령이나 내용 확인 기록이 있다
- 지침: 영향·대상 목록은 내용을 읽거나 재현 가능한 검색으로 만들고 그 명령을 남긴다
- 피함: 파일 이름·경로만 보고 분류하기, 검색 없이 caller 목록 만들기

### D7. 부정 주장의 대조군

- 질문: "없음·0건·영향 없음" 주장에 검색 범위와, 같은 방법이 실제 대상을 찾는다는 positive control이 있는가?
- 기본 severity: `medium`
- 적용 조건: 부재·0건·무영향을 근거로 결정하는 변경
- 결함 패턴: 잘못된 pattern이나 범위로 0건을 얻고 부재로 판정함
- PASS 근거: 부재 주장마다 검색 범위·pattern과, 같은 방법이 실제 대상을 찾는 양성 대조 결과가 있다
- 지침: "없음"을 주장하기 전에 같은 pattern과 범위가 알려진 대상을 찾는지 먼저 확인한다
- 피함: 대조 없이 0건을 부재로 판정하기, 범위를 좁혀 0건을 만들기

### D8. Tracked 문서의 시점 결합

- 질문: 장기 문서가 ignored 경로·plan 파일명·작업 단계 번호·session ID를 현재 규칙의 근거로 쓰지 않는가?
- 기본 severity: `low`
- 적용 조건: tracked 장기 문서와 owner README 변경
- 결함 패턴: 끝난 계획의 단계 이름이 현재 동작의 근거로 남음, 다른 clone에서 읽을 수 없는 local 증거를 인용함
- PASS 근거: 바뀐 장기 문서에서 ignored 경로·plan 파일명·작업 단계 번호·session ID를 찾는 검색이 근거 용도로 0건이다
- 지침: 장기 문서는 현재 책임·불변 조건·동작으로 설명하고, 시점 정보는 plan·checkpoint·evidence에 둔다
- 피함: 끝난 계획의 단계 이름을 현재 규칙의 근거로 쓰기, 다른 clone에서 읽을 수 없는 local 증거 인용하기
