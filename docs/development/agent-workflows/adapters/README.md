# Coding-agent host adapters

The repository contract is `AGENTS.md`. [Execution](../agent-execution-contract.md), [orchestration](../orchestration.md), [QA](../qa.md), and [child ownership](../request-intake/delegation.md) define shared responsibilities; the host adapter describes only how the current tool implements them. Read the adapter for the active host, not both by default.

| Host        | Entry                             | Project roles          | Host-only contract                                                              |
| ----------- | --------------------------------- | ---------------------- | ------------------------------------------------------------------------------- |
| Codex/OMX   | `AGENTS.md`                       | `.codex/agents/*.toml` | [Codex](./codex.md): model/effort cohorts, native routing, sandbox/OMX behavior |
| Claude Code | `CLAUDE.md` importing `AGENTS.md` | `.claude/agents/*.md`  | [Claude Code](./claude-code.md): native discovery, tools, permissions, skills   |

Names and similar task packets do not prove equivalent capabilities. Each lead checks the current host's loaded instructions, role/tool availability, effective permissions and source snapshot before dispatch. If unavailable, perform safe direct/sequential work or report a bounded blocker. Do not emulate another host's role, model, approval, or runtime state with prompt text.

`scripts/agents/common/index.mjs` exposes host-neutral intake, context discovery, plan readiness and cross-model packet/result/QA validation. It is advisory: it cannot admit a model, create a child or authenticate a host. The source owners for those exports remain the neutral root files. `scripts/agents/codex/` owns model profiles, role/effort routing, child/orchestration policy, model-run evidence and OMX session preflight. Tracked callers now use these owner paths directly; the temporary root compatibility imports have been removed after caller and fixture migration. `scripts/agents/claude/` keeps frozen `unsupported/unknown` runtime readiness and owns a separate finite static model candidate/admission policy. Its advisory descriptors never authorize dispatch or prove an effective model. `scripts/agents/bridge/` owns only the static one-shot fake-process boundary, not a live provider launcher.

| Source owner                             | Current modules                                                                                                                                                         | Caller boundary                                                                                            |
| ---------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| Neutral root + `common/index.mjs` facade | `intake-policy`, `domain-guide-registry`, `plan-readiness-policy`, `cross-model-handoff`                                                                                | Intake/plan/QA callers; never imports host policy                                                          |
| `codex/`                                 | `model-profiles`, `routing-policy`, `child-task-contract`, `orchestration-policy`, `model-run-evidence`, `fresh-session-smoke`, `session-contract`, `session-preflight` | Codex tests and CLI; mixed routing/child modules remain Codex-owned until semantics can actually be shared |
| `claude/`                                | finite native-subagent model policy plus fail-closed readiness marker                                                                                                   | Static task candidate/admission only; no dispatch, provider call or live qualification                     |
| `bridge/`                                | static one-shot review packet admission and fixed fake-CLI process lifecycle                                                                                            | No host model registry or provider execution; live qualification is separate                               |

`package.json`, smoke/preflight commands, fixture paths and source-inspection tests use the `codex/` owner directly. `session-contract`/`session-preflight` stay Codex/OMX-owned because they parse `.omx` context and call `omx`; a generic session name is not evidence of neutrality.

The [Codex child policy](./codex-delegation.md) and [Codex orchestration/recovery reference](../request-intake/orchestration-recovery.md) are host-owned extensions, not shared defaults. Existing Codex model cohorts and required Astra QA are not satisfied by a Claude review. Cross-model review requires a separately authorized evidence packet and independent qualification. A future CLI bridge owns process lifecycle and host-specific admission/argv factories; common validation must never import provider policy.

For a Codex↔Claude checker handoff, use the [host-neutral cross-model QA contract](./cross-model-handoff.md) with the canonical [QA packet](../qa.md#portable-qa-packet). It does not install a host, select a provider model or qualify direct CLI process delegation.

## Preparation versus live adoption

`repository-prepared` means the tracked instructions, native role definitions, selective tracking, regression tests and clean-clone handoff are ready for a future developer environment. This milestone does not require buying a provider plan, logging in, or invoking another host's agents. It is not evidence of actual role discovery, permission enforcement or model behavior.

`runtime-qualified` is a separate, explicitly authorized adoption gate on the real host: current instruction/role/tool loading, allowed and denied actions, executor test reporting, applicable skills, lifecycle/cleanup, and cross-provider handoff must be observed on frozen disposable fixtures. Until then, native and cross-model execution remain unqualified; metadata and static PASS cannot authorize blind dispatch. Unsupported features use a verified direct/manual path or remain a bounded blocker. Plugin setup and model execution have separate authority and evidence; neither a prepared repository nor a host installation implies live qualification.
