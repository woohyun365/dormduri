# KNU Roommate

강원대학교 재학생을 위한 생활패턴 기반 기숙사 룸메이트 매칭 서비스

## 서비스 소개

KNU Roommate는 강원대학교 재학생이 생활패턴이 맞는 기숙사 룸메이트를 더 예측 가능하게 찾을 수 있도록 돕는 시즌형 매칭 서비스입니다.

기존에는 단톡방이나 커뮤니티에 의존해 흡연 여부, 수면 패턴, 소음 민감도, 청결 기준 같은 핵심 생활 정보를 구조적으로 비교하기 어려웠습니다. 이 서비스는 학교 이메일 인증, 생활패턴 프로필, 시즌 운영, 건물 기반 매칭을 통해 더 현실적인 룸메이트 탐색 경험을 제공하는 것을 목표로 합니다.

상세한 서비스 설명은 [SERVICE.md](./SERVICE.md), 세부 운영 규칙은 [docs/04_policy/official/README.md](./docs/04_policy/official/README.md)를 기준으로 봅니다.

### 한눈에 보기

- 대상 사용자: 강원대학교 재학생
- 핵심 문제: 생활패턴이 맞지 않는 룸메이트 배정으로 인한 학기 중 스트레스
- 핵심 해결 방식: 생활패턴 프로필 + 원하는 룸메 조건 + 시즌/건물 기반 매칭
- 운영 특징: 비시즌 읽기 전용 탐색, 시즌 매칭 활성화
- 신뢰 장치: 학교 이메일 인증, 신고/차단 정책, 공개 정보 제한
- 구현 포인트: 시즌 상태 관리, 정책 기반 프로필 노출, 매칭 상태 전이

## 핵심 운영 제약

- 매칭 참여는 단순 가입이 아니라 `재학생 인증 + 시즌 + 건물 배정 입력` 조건을 만족해야 합니다.
- 비시즌과 시즌의 기능 범위가 다르며, 비시즌에는 읽기 전용 탐색 중심으로 동작합니다.
- 건물 정보는 선호 입력이 아니라 학교 배정 결과 입력이며, 시즌 중에는 자유 변경 대상이 아닙니다.
- 프로필은 필드마다 노출 범위와 수정 가능 범위가 다르고, 시즌 중 수정 범위가 제한됩니다.
- 매칭은 단순 요청/수락이 아니라 요청, 대화, 확정 상태 전이를 전제로 설계됩니다.

## 왜 이 프로젝트가 흥미로운가

이 프로젝트는 단순한 프로필 리스트 서비스가 아니라, 정책이 제품 동작을 직접 결정하는 상태 중심 서비스입니다.

- 시즌과 비시즌에 따라 같은 화면의 허용 액션이 달라집니다.
- 건물 배정 여부가 매칭 자격과 매칭 풀을 동시에 결정합니다.
- 프로필 구조, 노출 범위, 수정 가능 범위가 서로 분리되어 있습니다.
- 매칭은 요청만으로 끝나지 않고 대화, 확정, 종료 같은 상태를 가집니다.
- 공개 랜딩 페이지 카피도 실제 운영 정책과 일치해야 합니다.

즉 프론트엔드는 단순 UI 조합보다 정책 기반 상태 설계가 중요하고, 백엔드는 인증, 시즌 상태, 매칭 상태머신을 일관되게 제공해야 합니다.

## 현재 상태

- Frontend는 랜딩, 로그인, 회원가입, 비밀번호 재설정, 메인 탭 구조와 기본 테스트 기반이 있습니다.
- Backend는 NestJS 초기 스캐폴드 상태이며, 도메인 기능은 본격 구현 전 단계입니다.
- 서비스 정책은 [`docs/04_policy/official/README.md`](./docs/04_policy/official/README.md) 기준으로 정규화했습니다.
- Sprint 5에서는 이 정책 세트를 기준으로 프로필 모델, 시즌 게이트, 매칭 상태머신, 랜딩 카피를 UI에 반영할 예정입니다.

### 핵심 기능

- **학교 이메일 인증** — `@kangwon.ac.kr` 인증으로 재학생만 이용
- **생활패턴 프로필** — 생활패턴과 원하는 룸메 조건을 구조화해 비교
- **건물 기반 매칭** — 시즌에는 같은 건물 배정 사용자 중심으로 매칭
- **시즌형 운영** — 비시즌 읽기 전용 탐색, 시즌 매칭 활성화
- **안전 장치** — 신고/차단, 공개 정보 제한, 커뮤니티 안전 정책

## 시작하기

### 사전 요구사항

- Node.js 20+
- pnpm 9+

### 설치 및 실행

```bash
# 의존성 설치
pnpm install

# 환경변수 설정
cp apps/web/.env.example apps/web/.env

# 개발 서버 실행 (web + api 동시)
pnpm dev
```

| 앱             | URL                                                |
| -------------- | -------------------------------------------------- |
| Web (Frontend) | http://localhost:3000                              |
| API (Backend)  | `PORT` 환경변수 기준 (예: `http://localhost:3001`) |
